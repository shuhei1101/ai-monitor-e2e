# Issue #970: タスク編集画面の追加

案は kebab-case 名前順で縦に並べる。
どちらの案も編集項目・保存挙動は同じで、保存・取り消しボタンの置き場所だけが違う。

## a-sticky-actions

採用案。
保存・取り消しを画面下部の固定バーに置く案。
本文が長くスクロールしても操作ボタンが常に見える。
スマホ幅でもデスクトップと同じ構造を保てる点を評価して採用した。

[この案を開く](a-sticky-actions/)

## b-header-actions

不採用（比較用に残す）。
保存・取り消しを画面名と同じヘッダー行に置き、ヘッダーごとトップバー直下に貼り付ける案。
デスクトップの業務画面で見慣れた配置に揃う。

[この案を開く](b-header-actions/)

## 両案に共通する仕様

- 編集項目はタイトルと本文の 2 項目のみ。
- 画面を開いた時点で現在値が入力欄に入っている。
- 保存中は保存ボタンをローディング表示にして無効化し、二重送信を防ぐ。
- 保存に失敗したときはフォーム上部のバナーに要約を出し、項目単位の理由は入力欄の直下に出す。
- 取り消しは変更があるときだけ確認ダイアログを表示し、変更がないときは確認なしで離脱する。

## モック上の制約

- タスク一覧画面は本 epic でレイアウトを変更しないためモックを持たない。
  一覧画面への遷移はトーストによる疑似表示にしている。
- 画面上部の「デモ用: 保存結果」は保存成功時と保存失敗時の表示を切り替えるためのモック専用スイッチで、実画面には表示しない。
