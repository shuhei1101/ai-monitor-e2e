# テスト実行方法

プロジェクトのテスト種別ごとの実行コマンドと前提条件。

## 前提

- Python 3.12 以上（標準ライブラリのみ。パッケージのインストールは不要）
- テストランナーは `unittest`
- 実装は `src/` に置くため、実行時に `PYTHONPATH=src` を付ける
- 実行はリポジトリルートから行う
- 起動が必要な依存サービス（DB / 外部 API）はない

テストの配置:

```
tests/
├── unit/                     # 単体テスト（src をミラー。1 テストファイル = 1 実装ファイル）
│   └── tasks/
├── integration/              # 結合テスト（1 テストファイル = インターフェース定義 1 ページ）
│   └── tasks/
└── e2e/
    └── 単一ユースケース/     # 1 テストファイル = 単一 UC シナリオ 1 ページ
```

## 非機能要件テスト

なし

`設計図/非機能要件.md` が未整備のため、アプリ全体として実測する項目はまだない。
subsystem 単位の非機能の制約（応答時間など）は、各インターフェース定義の `## 制約` に書いたうえで結合テストの中で確認する。

## E2E テスト

`unittest` で実行。

**前提:**

- 画面が無いため、単一 UC シナリオの検証はタスクサービスの公開関数を通した一連の操作で行う
- テストファイルは `tests/e2e/単一ユースケース/test_{機能名}.py` に置き、シナリオの H2 見出しと 1 テスト関数を機械対応させる
- 対象は `設計図/シナリオ/単一ユースケース/**` と 1:1

**全件実行:**

```bash
PYTHONPATH=src python3 -m unittest discover -s tests/e2e -t .
```

**個別シナリオ実行:**

```bash
PYTHONPATH=src python3 -m unittest {シナリオテストのモジュールパス}
```

## 結合テスト（バック）

`unittest` で実行。

**前提:**

- 外部依存が無いため Mock は使わず、インメモリのタスクストアを実物のまま組み立てて渡す
- テストファイルは `tests/integration/{ドメイン}/test_{操作の英語名}.py` に置き、インターフェース定義のフロー 1 本 = 1 テスト関数に対応させる
- 対象は `設計図/インターフェース定義/バックエンド/**` と 1:1

**全件実行:**

```bash
PYTHONPATH=src python3 -m unittest discover -s tests/integration -t .
```

**個別エンドポイント実行:**

```bash
PYTHONPATH=src python3 -m unittest {結合テストのモジュールパス}
```

## 単体テスト（バック）

`unittest` で実行。

**前提:**

- 外部依存なし（引数で受け取った値だけを扱う）
- テストファイルは `src/` をミラーした `tests/unit/{パッケージ}/test_{モジュール名}.py` に置く
- 対象は `設計図/モジュール構成/**` の単体テスト表と 1:1

**全件実行:**

```bash
PYTHONPATH=src python3 -m unittest discover -s tests/unit -t .
```

**個別ファイル実行:**

```bash
PYTHONPATH=src python3 -m unittest {単体テストのモジュールパス}
```

## 結合テスト（フロント）

なし

## 単体テスト（フロント）

なし

## 外部疎通テスト

なし

外部 API を呼ばないため、実接続を確認する対象がない。
