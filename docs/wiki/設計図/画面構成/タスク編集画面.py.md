# タスク編集画面

画面: `src/screens/task_edit.py`
モック: `docs/mock/pages/task-edit/issues/1069/a-single-column/`

登録済みのタスクのタイトル・本文を編集する画面。
本サブシステムでは、タスク詳細取得による初期表示・入力欄・保存操作・入力チェックのインライン表示・保存後の一覧画面への遷移までを確定する。
編集を保存せずに一覧画面へ戻る中止導線は兄弟サブシステム #1081（PR #1084）の担当のため、本ページでは要素の設置だけを持つ。
バックエンドと同じ Python 実行環境の画面層として実装するため、要素は HTML のタグではなく画面層が組み立てる表示要素として定義する。

## 要素一覧

| 要素 | 種類 | 位置 | 説明 | 表示条件 | 必須 | 制限 | 初期値 | 取得元 | アクション | 補足 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 画面見出し | label | ヘッダー | 画面名を示す | 常時 | - | - | `タスク編集` | - | - | - |
| 保存失敗メッセージ | label | フォーム本体上部 | 保存の呼び出しが失敗したことを示す | 直前の保存操作で `タスク更新` が例外を返したとき | - | - | 非表示 | - | - | 文言は ※4 |
| タイトル入力欄 | input | フォーム本体 | 編集対象のタスクのタイトルを入力 | 常時 | ✅ | 1〜100 文字 | 取得値 | `タスク詳細取得.title` | - | 判定内容は ※1 |
| タイトルエラーメッセージ | label | タイトル入力欄の直下 | タイトルが入力チェックに違反したことを示す | 直前の保存操作でタイトルが入力チェックに違反したとき | - | - | 非表示 | - | - | 文言は ※2 |
| 本文入力欄 | textarea | フォーム本体 | 編集対象のタスクの本文を入力 | 常時 | - | 1000 文字以内 | 取得値（本文が未設定なら空文字） | `タスク詳細取得.content` | - | 判定内容は ※1 |
| 本文エラーメッセージ | label | 本文入力欄の直下 | 本文が入力チェックに違反したことを示す | 直前の保存操作で本文が入力チェックに違反したとき | - | - | 非表示 | - | - | 文言は ※2 |
| 本文の補助文言 | label | 本文入力欄の直下 | 本文を空のままでも保存できることを示す | 常時 | - | - | `本文は空のままでも保存できます。` | - | - | 本文エラーメッセージとは同時に表示され得る |
| 保存ボタン | button | フォーム本体下部 | 入力内容でタスクを更新 | 常時 | - | - | `保存` | - | クリックで入力チェックを行い、通過したら `タスク更新` を呼び、成功したらタスク一覧画面へ遷移 | 活性条件は ※3 / 遷移先は ※5 |
| 編集の中止ボタン | button | フォーム本体下部 | 入力内容を保存せずに一覧画面へ戻る | 常時 | - | - | `編集の中止` | - | 本サブシステムでは押下時の処理を持たない | 押下時の処理は ※6 |

※1: 保存ボタンの押下時に、タイトル・本文の順で次の判定を行う。
タイトルは前後の空白を除いた文字数が 1 文字以上 100 文字以内であること。
本文は入力値そのままの文字数が 1000 文字以内であること。
いずれかに違反した場合は `タスク更新` を呼ばず、違反した入力欄のエラーメッセージだけを表示して編集画面に留まり、書き換えた入力内容をそのまま保持する。
判定値は定数として定義し、タイトルの下限は「空文字かどうか」の直接比較ではなく下限の定数との比較で判定する（バックエンドで下限判定の欠落が 6 世代連続して再発しているため、画面側でも判定の形をバックエンドと揃えて欠落を検出しやすくする）。
タイトルは前後の空白を除いた値を `タスク更新` へ渡し、判定した値と送る値を一致させる（画面を通過した入力がバックエンドの検証で弾かれる状態を作らない）。
本文は前後の空白も内容の一部として扱うため除去しない。

※2: 入力チェックのエラーメッセージは判定ごとに次の文言にする。

| 判定 | 文言 |
| --- | --- |
| タイトルが下限未満（前後の空白を除いて 0 文字） | `タイトルを入力してください。` |
| タイトルが上限超過 | `タイトルは {タイトルの上限} 文字以内で入力してください。` |
| 本文が上限超過 | `本文は {本文の上限} 文字以内で入力してください。` |

`{タイトルの上限}` / `{本文の上限}` は判定に使う定数から組み立て、判定条件と文言が食い違わないようにする。
下限未満は「未入力」を指す固定文言にする（採用モック・単一 UC シナリオの異常シナリオが期待している文言に合わせるため）。

※3: 保存ボタンは常に押せる状態にし、入力内容による非活性化を行わない。
タイトルが空の状態でも押下でき、押した時点で入力チェックが走ってインライン表示される（epic #1069 の PR #1072 で確定した画面仕様）。

※4: 保存失敗メッセージは `タスク更新` が返した例外ごとに次の文言にする。

| 例外 | 文言 |
| --- | --- |
| `ValidationError` | `保存できませんでした。入力内容を確認してください。` |
| `TaskNotFoundError` | `タスクが見つかりません` |

いずれの場合もタスク一覧画面へ遷移せず、書き換えた入力内容を保持したまま編集画面に留まる。
`TaskNotFoundError` の文言は別サブシステム #1079（PR #1083）のタスク一覧画面の未検出メッセージと同一にする。

※5: 遷移先はタスク一覧画面（画面識別子 `task-list`）で、遷移時に引き渡す値は持たない。
編集画面・一覧画面の URL 形式は別サブシステム #1079 が確定するため、本ページでは新規に定義しない。

※6: 編集の中止ボタンの押下時の処理（入力変更の有無の判定・破棄確認ダイアログの表示・破棄しての遷移）は兄弟サブシステム #1081（PR #1084）の担当範囲。
本ページでは要素の設置までを確定し、押下時の挙動と破棄確認ダイアログの要素は定義しない。
PR #1084 の同名ページが保存ボタンについて同じ扱い（要素は置くが押下時の処理を持たない）をしており、両ページを master へ集約する際は両者の要素一覧の和集合になる。

## 補足

- 採用モックには保存完了のトーストがあるが、単一 UC シナリオが表示の有無を期待値に含めておらず、システム要件でもスコープ外としているため、本ページでは要素として持たない。
- タイトル入力欄・本文入力欄・保存ボタン・編集の中止ボタン・画面見出しの 5 要素は PR #1084 と同一定義にする（ブランチ系列が別で成果物が合流しないため意図的に重複させており、master へ集約する際に同内容として解消できる状態にする）。
