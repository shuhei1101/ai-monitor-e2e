# タスク一覧画面

画面: `src/screens/task_list.py`
モック: `docs/mock/pages/task-list/issues/1069/existing/`

登録されているタスクを一覧表示する画面。
本サブシステムでは、タスク編集画面で保存した内容が反映された状態を確認できる戻り先として、一覧の表示までを確定する。
一覧から編集画面へ遷移する導線は別サブシステム #1079（PR #1083）の担当のため、本ページでは行の選択時の処理を持たない。
バックエンドと同じ Python 実行環境の画面層として実装するため、要素は HTML のタグではなく画面層が組み立てる表示要素として定義する。

## 要素一覧

| 要素 | 種類 | 位置 | 説明 | 表示条件 | 必須 | 制限 | 初期値 | 取得元 | アクション | 補足 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 画面見出し | label | ヘッダー | 画面名を示す | 常時 | - | - | `タスク一覧` | - | - | - |
| タスク表 | table | 本体 | 取得したタスクを 1 行 1 件で並べる | 取得件数が 1 件以上のとき | - | 件数上限なし | 取得結果の全件（識別子の昇順） | `タスク一覧取得`（戻り値） | - | 表示項目は ※1 |
| 識別子見出し | label | 表ヘッダー | 識別子列の見出し | タスク表の表示時 | - | - | `ID` | - | - | - |
| タイトル見出し | label | 表ヘッダー | タイトル列の見出し | タスク表の表示時 | - | - | `タイトル` | - | - | - |
| 本文見出し | label | 表ヘッダー | 本文列の見出し | タスク表の表示時 | - | - | `本文` | - | - | 列を持つ理由は ※1 |
| タスク行 | row | 表本体 | タスク 1 件を表す行 | タスク表の表示時 | - | - | - | - | 本サブシステムでは選択時の処理を持たない | 選択時の処理は ※2 |
| 識別子セル | label | 表本体 | タスクの識別子 | タスク表の表示時 | - | - | 取得値 | `タスク一覧取得.[].id` | - | - |
| タイトルセル | label | 表本体 | タスクのタイトル | タスク表の表示時 | - | - | 取得値 | `タスク一覧取得.[].title` | - | 保存した内容の反映をここで確認する |
| 本文セル | label | 表本体 | タスクの本文 | タスク表の表示時 | - | - | 取得値（本文が未設定なら空文字） | `タスク一覧取得.[].content` | - | 保存した内容の反映をここで確認する |
| 空状態メッセージ | label | 本体 | 登録が 0 件であることを示す | 取得件数が 0 件のとき | - | - | `タスクがありません` | - | - | 0 件でも画面が成立することを担保する |

※1: 表示項目は識別子・タイトル・本文の 3 列にする。
単一 UC シナリオ「正常シナリオ」の期待値「一覧の対象タスクの行に、変更後のタイトル・本文が表示されている」を本画面で確認するため、本文の列を持つ。
シナリオの補足に「保存後の戻り先となる一覧画面は #1085 が最小構成で自前実装する。一覧の行に変更後のタイトル・本文が表示されることは、その最小構成の一覧画面で確認する」と明記されている（story #1075 の決定）。
別サブシステム #1079（PR #1083）の同名ページは識別子・タイトルの 2 列で本文を持たないため、本ページとは本文の列の分だけ差がある（扱いは ※3）。

※2: タスク行の選択時の処理（遷移先の決定・`タスク詳細取得` の呼び出し・初期表示値の引き渡し・未検出メッセージの表示）は別サブシステム #1079（PR #1083）の担当範囲。
本ページでは要素の設置までを確定し、選択時の挙動と未検出メッセージの要素は定義しない。
編集画面へ遷移する導線を持たないため、識別子セルの値は表示のみに使う。

※3: 本ページと PR #1083 の同名ページは同じ画面（`src/screens/task_list.py`）を定義しており、本文の列の有無と未検出メッセージの有無で食い違う。
本文の列は本 story の受入基準を満たすために必要な一方、PR #1083 側は epic #1069 の横断要件「一覧画面のレイアウトは変更しない」を根拠に持たない判断をしている。
どちらを残すかは master へ集約する時点で epic レイヤーの判断が要る。

## 補足

- 一覧の取得元となる `タスク一覧取得` は本サブシステムの担当範囲外で、story #1075 の決定によりバックエンド #1080 が提供する。
  本 PR の base にはまだ入っていないため、画面側は依存の関数型として受け取る形にして、取得元が入るまでは差し替えた関数で設計・テストを進める。
  インターフェースは #1073 が確定した定義（パラメータなし / 戻り値は `id` / `title` / `content` を持つタスクの配列を識別子の昇順で全件 / 例外なし）に一致する。
- 画面見出し・タスク表・識別子見出し・タイトル見出し・タスク行・識別子セル・タイトルセル・空状態メッセージの 8 要素は PR #1083 と同一定義にする（ブランチ系列が別で成果物が合流しないため意図的に重複させており、master へ集約する際に同内容として解消できる状態にする）。
