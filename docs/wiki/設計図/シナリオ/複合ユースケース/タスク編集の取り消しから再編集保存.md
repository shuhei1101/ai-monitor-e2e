# タスク編集の取り消しから再編集保存

編集を取り消して変更を破棄したあと、あらためて編集して保存し一覧へ反映するまでの業務シナリオ。
編集画面からの離脱（取り消し）と再進入（再編集）のつなぎ目を検証する。

- 対応テストファイル: `tests/e2e/複合ユースケース/test_タスク編集の取り消しから再編集保存.py`

## 正常シナリオ

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | なし（実環境で実行） | - |
| タスク | 編集対象のタスクを 1 件登録済み | タイトル・本文とも初期値を入れておく |

### フロー

```mermaid
flowchart TD
  subgraph FOCUS["検証対象: 破棄した変更が再編集に残らない"]
    UC1([タスク編集を取り消す:正常シナリオ<br>（変更あり）]) -->|確認ダイアログで破棄・一覧へ戻る<br>タスクは編集前のまま| UC2([タスクを編集して保存する:正常シナリオ])
  end

  U0([ユーザー]) -->|一覧から対象タスクを選び<br>編集画面で内容を書き換えて取り消す| UC1
  UC2 -->|保存完了・一覧へ戻る| DONE([一覧に再編集後の内容が表示された状態])

  click UC1 "../単一ユースケース/タスク編集を取り消す.md#正常シナリオ変更あり"
  click UC2 "../単一ユースケース/タスクを編集して保存する.md#正常シナリオ"
```

### 期待値

- 一覧に再編集後のタイトルと本文が表示されている
- 取り消し時に入力していた内容は一覧にも対象タスクにも残っていない

### 補足

- 再編集で編集画面を開き直した時点の入力欄には、取り消し前の入力ではなく編集前の現在値が入っている。
- 破棄が効いているかは再編集の入力欄ではなく、最終的な一覧の表示で判定する（中間状態をアサートしない）。

## 異常シナリオ（保存に失敗した後に取り消す）

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | なし（実環境で実行） | - |
| タスク | 編集対象のタスクを 1 件登録済み | タイトル・本文とも初期値を入れておく |
| 入力 | タイトルを空にして保存 | 既存 API のバリデーション失敗を決定的に誘発 |

### フロー

```mermaid
flowchart TD
  subgraph FOCUS["検証対象: 保存失敗の状態から取り消しで離脱できる"]
    UC1([タスクを編集して保存する:異常シナリオ<br>（タイトルが空）]) -->|保存されず編集画面に留まる<br>入力値は保持されたまま| UC2([タスク編集を取り消す:正常シナリオ<br>（変更あり）])
  end

  U0([ユーザー]) -->|一覧から対象タスクを選び<br>タイトルを空にして保存| UC1
  UC2 -->|確認ダイアログで破棄・一覧へ戻る| DONE([一覧が編集前のままの状態])

  click UC1 "../単一ユースケース/タスクを編集して保存する.md#異常シナリオタイトルが空"
  click UC2 "../単一ユースケース/タスク編集を取り消す.md#正常シナリオ変更あり"
```

### 期待値

- 一覧に編集前のタイトルと本文が表示されている
- 対象タスクが編集前の内容のまま更新されていない

### 補足

- 保存失敗はエラー表示そのものではなく、失敗後も取り消し導線で離脱できて一覧が汚れないことを検証する。
- 保存失敗の表示位置・文言は単一ユースケース側の責務とする。
