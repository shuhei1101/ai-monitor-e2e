# タスク編集

タスク一覧から選んだ既存タスクの内容を編集して保存する単一ユースケース。
編集の取りやめ・入力不備・他ユーザーとの競合までを本ファイルに集約する。

- 対応テストファイル: `tests/e2e/単一ユースケース/test_task_edit.py`

## 正常シナリオ

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | なし（実環境で実行） | - |
| `createTask` | 一覧に表示される編集対象のタスク | `title: 初期タイトル` / `content: 初期本文` |

### フロー

```mermaid
sequenceDiagram
  actor U as ユーザー
  participant FE as 画面（フロントエンド）
  participant BE as バックエンド API
  participant DB as タスクストア

  U->>FE: タスク一覧画面を開く
  FE->>BE: タスク一覧を取得
  BE->>DB: 登録済みタスクを検索
  BE-->>FE: タスク一覧
  FE-->>U: 一覧に対象タスクを表示
  U->>FE: 対象タスクの編集導線を選択
  FE->>BE: GET /tasks/{task_id}
  BE->>DB: 対象タスクを検索
  BE-->>FE: 対象タスク
  FE-->>U: 編集画面に現在の内容を初期表示
  U->>FE: タイトルと本文を変更して保存
  FE->>FE: 入力バリデーション
  FE->>BE: PATCH /tasks/{task_id}
  BE->>DB: 対象タスクを更新
  BE-->>FE: 更新後のタスク
  FE-->>U: 一覧へ戻り編集後の内容を表示
```

### 期待値

- 一覧画面に編集後のタイトルと本文が表示されている
- タスクストアの該当タスクが編集後の値になっている

### 補足

- 保存は既存の `PATCH /tasks/{task_id}` を利用する（epic #557 の横断要件「保存時は既存 API を利用する」）。
- 編集画面の初期表示は、一覧で選択したタスクの登録済みの値をそのまま表示する。

## 異常シナリオ（タイトルが空）

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | なし（実環境で実行） | - |
| `createTask` | 一覧に表示される編集対象のタスク | `title: 初期タイトル` / `content: 初期本文` |
| 入力 | タイトルを空にして保存 | 検証失敗を決定的に誘発 |

### フロー

```mermaid
sequenceDiagram
  actor U as ユーザー
  participant FE as 画面（フロントエンド）
  participant BE as バックエンド API
  participant DB as タスクストア

  U->>FE: 一覧から対象タスクの<br>編集画面へ遷移
  FE->>BE: GET /tasks/{task_id}
  BE->>DB: 対象タスクを検索
  BE-->>FE: 対象タスク
  FE-->>U: 編集画面に現在の内容を初期表示
  U->>FE: タイトルを空にして保存
  FE->>FE: 入力バリデーション失敗
  FE-->>U: タイトル欄にエラーを表示
```

### 期待値

- タイトル入力欄にエラーが表示され、編集画面にとどまっている
- タスクストアの該当タスクが編集前の値のままになっている

### 補足

- タイトルは 1 文字以上 100 文字以内が制約（`設計図/バックエンド結合/タスク更新.py.md`）。
  代表として空文字を扱い、文字数超過は結合ドキュメント側でカバーする。

## 異常シナリオ（同時編集競合）

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | なし（実環境で実行） | - |
| `createTask` | 一覧に表示される編集対象のタスク | `title: 初期タイトル` / `content: 初期本文` |
| 別ユーザーの保存 | 編集画面を開いた後、同じタスクを別ユーザーが先に更新済みにする | 競合を決定的に誘発 |

### フロー

```mermaid
sequenceDiagram
  actor U as ユーザー
  participant FE as 画面（フロントエンド）
  participant BE as バックエンド API
  participant DB as タスクストア

  U->>FE: 一覧から対象タスクの<br>編集画面へ遷移
  FE->>BE: GET /tasks/{task_id}
  BE->>DB: 対象タスクを検索
  BE-->>FE: 対象タスク（更新前）
  FE-->>U: 編集画面に現在の内容を初期表示
  Note over BE,DB: 別ユーザーが同じタスクを<br>先に更新して保存
  U->>FE: 内容を変更して保存
  FE->>BE: PATCH /tasks/{task_id}
  BE->>DB: 開いた時点からの更新を検出
  BE-->>FE: 競合エラー
  FE-->>U: 他ユーザーが更新済みである旨を表示
```

### 期待値

- 編集画面に競合エラー（他ユーザーが更新済みである旨）が表示されている
- タスクストアの該当タスクが別ユーザーの更新内容のままで、こちらの変更は保存されていない

### 補足

- 本シナリオは複合ユースケース `タスク編集から他ユーザー編集` の異常シナリオ（同時編集競合）から参照される。
- 現行の `PATCH /tasks/{task_id}` には競合を検出する仕組みがないため、実現には更新日時等を用いた競合検出の追加が必要。
